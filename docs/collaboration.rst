Collaboration and shared links
==============================

There are two ways to collaborate: authenticated study access for ongoing team
members, and scoped shared links for limited external collection or review.

Choose the access method
------------------------

Use an authenticated account when a person needs recurring access, must work
across subjects or visits, or needs an attributable application identity. Use a
shared link only for a narrow, time-limited workflow.

Shared-link capabilities
------------------------

A link can be configured for:

* view or add-data capability;
* a particular subject;
* a particular visit;
* a study group;
* selected form sections;
* an expiry date/time; and
* a maximum number of uses.

The available scope depends on the study and the creator's permissions. A link
does not grant broader access than its saved configuration.

Create a shared link
--------------------

#. Open the study's sharing area.
#. Select the required capability: **View** or **Add data**.
#. Restrict the subject, visit, group, and sections as tightly as possible.
#. Set a short expiry and a realistic maximum-use count.
#. Create the link.
#. Test it in a signed-out/private browser window.
#. Send it through an approved secure channel.

Bulk links
----------

Bulk creation can generate multiple scoped links, for example one per subject or
visit. Export the generated links as CSV when offered. Treat that CSV as
sensitive access material: possession of an active link may be sufficient to use
the configured capability.

Monitor and revoke
------------------

Review active links regularly. Revoke a link immediately when it is sent to the
wrong recipient, no longer needed, or shows unexpected use. Expiry and maximum
uses limit exposure but do not recall a link that has already been used.

Safe-sharing checklist
----------------------

* Never create an unscoped add-data link when a subject-specific link will do.
* Do not put subject identifiers in email subject lines or public messages.
* Verify the link in a private session before distribution.
* Record the recipient, purpose, expiry, and revocation decision.
* Prefer authenticated accounts for identifiable or long-running activity.
* Revoke links at study close-out.

Editing conflicts
-----------------

Shared-link and authenticated users may reach the same entry. Revision-token
checks and conflict resolution protect against silent last-write-wins behavior.
When a conflict appears, compare each field or table change, preserve the correct
value, and document the resolution when required by the study process.
